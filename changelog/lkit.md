# lkit Version History

[lkit](https://github.com/landscape-router/landscape-kit) is the companion tooling for
Landscape: a terminal console plus command line for installing and operating Landscape
instances, covering first deployment, migrating manual deployments, updates, version switching,
repair, backup, network takeover, and service lifecycle management. It also ships the Terrain L2
fallback channel (flare): when the normal IP path is unavailable, the `lflare` client opens an
encrypted layer-2 emergency management connection to the router. Only lkit's own releases are
listed here, with the parts that adapt to the main project called out. For the main project, see
[Version History](./).

Its version numbers run on their own line, so do not read them as Landscape versions. Every
release has a short summary, with the detailed entries folded away behind a collapsible block.

Headings marked <Badge type="warning" text="pre-release" /> are pre-releases. These early lkit tags
have no GitHub release, so they are judged by the `-rc.N` in the version; where a release exists,
GitHub's pre-release flag is what counts.

Only releases from the **last six months** (after 2026-04-11) are listed here, which currently
covers every lkit release.

## Unreleased

`lkit self update` is now accepted as an alias for `lkit self upgrade`. The change is on main but
had not been released as of 2026-10-11.

## v0.6.2 (2026-10-09)

flare now fails loudly on a protocol version mismatch, and a handshake interrupted by a
duplicated capture is fixed.

::: details Detailed changes

- When flare sees a protocol version mismatch it replies with a plaintext error frame and fails
  loudly instead of stalling quietly.
- Fixed the bridge double-capture topology: a DISCOVER captured twice no longer breaks the
  handshake.
- flare relay tuning constants and the scrypt exponent moved into landscape-terrain-proto, shared
  by both sides.
- Removed unused re-exports and dead code from the service crate.
  :::

## v0.6.1 (2026-10-06)

Includes v0.6.1-rc.1 and rc.2. Small fixes: loopback traffic stays out of environment proxies.

::: details Detailed changes

- Loopback traffic stays direct and is no longer picked up by environment proxies.
- Fixed a mock mirror refresh test that was affected by path overrides.
  :::

## v0.6.0 (2026-10-01 → 2026-10-06)

Includes v0.6.0-rc.2. The focus here is adapting the install flow to newer versions of the main
project, plus a broad pass on console interaction. Init configuration is now generated through
`landscape config`, which targets Landscape 0.25.1 and later.

::: details Detailed changes

- Init configuration is now generated by calling the main project's `landscape config`, matching
  Landscape 0.25.1 and later.
- Adapted to the presence-driven semantics of that config subcommand, where behavior depends on
  which arguments are passed.
- Port checks take the install state into account: a port held by a running Landscape instance
  is treated as expected rather than a conflict.
- The console is keyboard-first, dialogs and lists share one layout, key hints live in the
  status bar, and the status area is capped at two rows.
- Snapshots now pin dialogs, blocking screens, and whole-screen layouts, backed by a
  docker-rendered layout gallery and a real-PTY panel walk.
- flare: F3 switches language in any context, an explicit auth rejection stops retries, log rows
  are budgeted physically, and the TUI interaction contract matches the console.
- Housekeeping: panel background work routes through per-panel ops traits, and docs and test
  scaffolding were refreshed.
  :::

## v0.4.0 (2026-08-19)

A focused pass on flare relay concurrency and half-close handling, plus the removal of the hard
memory limit at install time.

::: details Detailed changes

- The hard memory limit at install time is gone.
- flare relay: connection bursts are absorbed, server listeners are pooled, relay reads are
  decoupled from writes, and bulk traffic no longer starves server tasks.
- flare relay: data survives a half-close, EOF propagates after an active close, data is flushed
  before closing, and stale relay messages are rejected.
- Testing: concurrent connection lifecycles and sustained TCP transfers are covered; CI runs
  scenarios in parallel with a shared build cache.
  :::

## v0.3.0 (2026-08-18)

Migration becomes two-phase and is delegated to the resident daemon; flare gets an interactive

::: details Detailed changes

- flare gained an interactive session UI, was split into modules with i18n, and its mapping

  :::

## v0.2.0-rc.2 (2026-08-17) <Badge type="warning" text="pre-release" />

The release that made lkit self-hosting: its own territory, a resident daemon that runs
operations on its behalf, and systematic tests for install, uninstall, and migration.

::: warning Breaking changes
CentOS 7 and Stream are no longer supported. The "none" deployment mode is removed, so the
distribution's init system (systemd / openrc / sysvinit) is required. Uninstall now only cleans
up Landscape and leaves lkit itself and its daemon in place.
:::

::: details Detailed changes

- A resident lkit daemon can run operations on behalf of the frontend, and recovers interrupted
  transactions.
- Service management is abstracted, supporting systemd, openrc, and sysvinit.
- lkit got its own territory, separate from the Landscape install root, so uninstall no longer
  touches lkit or its daemon.
- `lkit self install/upgrade/remove` manages lkit itself.
- Migration: manually deployed Landscape instances can be adopted into lkit.
- A common software installer with Docker support; the software panel manages Landscape base
  packages.
- Mirrors: availability probing, Tencent and Huawei mirrors, index refresh after switching or
  restoring, support for Fedora's two mirror layouts, and CD-ROM sources commented out when
  switching.
- Docker install sources also gained Tencent and Huawei options.
- ifupdown network takeover is supported.
- `lkit reinit` rebuilds network configuration with a protection backup first.
- The console was split into per-domain modules, gained backup/restore and update panels and
  install cancellation, and its backup list became a headered size-aware table.
- The network takeover wizard was reworked, and the install result screen can confirm the
  takeover directly.
- flare: the terrain L2 flare protocol was folded into the workspace, and flare became a
  daemon-hosted service with install-time psk provisioning and interactive recovery.
- flare protocol work: v2 added encrypted sessions and mutual auth, v4 sealed DISCOVER/RESP with
  anti-replay, v5 stretches the master key with scrypt, derives per-direction handshake keys, and
  binds auth frames to the MAC. MAC-spoofed DoS was hardened against throughout.
- flare: layer-2 port forwarding over a userspace smoltcp stack, plus a fix for a Windows
  transport deadlock.
- Installation is refused when a valid install state already exists.
- Testing: extensive e2e and scenario coverage, including real daemon delegation inside
  systemd-nspawn.
  :::
